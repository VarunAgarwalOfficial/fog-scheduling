Fog scheduling

Users send tasks to their nearest fog node. A fog node is close but small, so it keeps a few tasks and sends the rest to a larger cloud that takes a few ticks to reach. The scheduling policy decides which tasks stay and what runs first. Every policy runs on the same tasks, over many independent workloads, and the results come with 95% confidence intervals. What it finds is what queueing theory predicts; the last section checks that.

Settings

Changes rerun everything. The settings are kept in the address, so a link reproduces the page. Seeds run from the seed given upwards; each seed is one workload, and the network layout stays the same.

      Against queueing theory: one queue

      Take the network away except for one fog node that keeps every task: a single server, 50 users, work of 1 to 9 ticks. Each policy here is only its order; nobody is sent away.
